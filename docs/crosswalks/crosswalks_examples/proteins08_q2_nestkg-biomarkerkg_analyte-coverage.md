| Measure | Count |

**Two numbers, two different questions.** The 93.9% says the join is nearly lossless as a *lookup*: take almost any protein biomarker and NeST has an entry for it. The 114 is the number that governs the interesting query — the system-neighbourhood analysis in Q1 — because you can only ask "what else is in this biomarker's assembly?" for a protein whose system membership NeST actually publishes. NeST suppresses `has_member` edges above its system-size cutoff, so a protein can be in the IAS interaction network, and therefore a NeST protein, without being retrievable as a member of a specific system.

**Why the hit rate is so high.** Clinical protein biomarkers are, almost by construction, well-studied abundant proteins with dense interaction data — exactly the proteins an interaction-derived map like NeST retains. Contrast the reverse direction: those same 230 are 1.4% of NeST's 16,767 proteins. This join is a *deep, narrow* one — near-complete on the BiomarkerKG side, marginal on the NeST side — so always state which side a percentage is taken over.

**The 15 misses** are BiomarkerKG analytes with no NeST entry at all: proteins measured clinically but absent from the cancer interaction map NeST is built on.

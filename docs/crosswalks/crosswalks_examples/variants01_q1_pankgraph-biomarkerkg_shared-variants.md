**Why this answers the question, and why the top row is the validation.** PanKgraph is a *pancreas* knowledge graph. The single largest disease behind its shared variants is **type 2 diabetes mellitus** — 43 of 214, three and a half times the next entry. That is exactly what a correct join should produce: the pancreatic-islet variant set overlapping the clinical marker set precisely where pancreatic biology and clinical risk assessment meet. Coronary artery disorder at 12 follows the same logic through the metabolic axis.

The remainder — osteoarthritis, rheumatoid arthritis, lupus, IBD, psoriasis — is the autoimmune/inflammatory GWAS backbone, unsurprising given that both graphs draw on common-variant association studies.

**What the join buys.** PanKgraph knows a variant is relevant to pancreatic biology but not whether anyone measures it clinically; BiomarkerKG knows a variant is a susceptibility or diagnostic marker but nothing about islet biology. The join yields *variants that are both* — a short, concrete list for a risk-panel question.

**Two mechanical traps worth carrying forward.** (1) PanKgraph's dbSNP references are **literals**, not IRIs, so `IRI(CONCAT(...))` matched against them returns a clean, wrong 0 — this was control-tested on an rsID PanKgraph provably has. Reduce both sides to the bare rsID string. (2) Adding the ubergraph label hop to the main join made the query return 0 rows; resolving the 12 disease labels in a separate `VALUES` query worked immediately.

PREFIX obo: <http://purl.obolibrary.org/obo/>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>
SELECT ?rs ?disease WHERE {
  GRAPH <https://purl.org/okn/frink/kg/pankgraph> {
    ?g rdfs:seeAlso ?snp .
    FILTER(STRSTARTS(STR(?snp),'https://api.ncbi.nlm.nih.gov/variation/v0/refsnp/'))
  }
  BIND(REPLACE(STR(?snp),'^.*/refsnp/','') AS ?rs)

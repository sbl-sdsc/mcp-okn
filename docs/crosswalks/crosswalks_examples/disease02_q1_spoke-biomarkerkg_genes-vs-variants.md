🧠 **Assistant**

**Why the join is required, and what changed.** SPOKE asserts disease→gene associations (`ASSOCIATES_DaG`) keyed on DOID but names no variants. BiomarkerKB catalogues specific variant entries — a dbSNP rsID assessed as present in a named gene — keyed on disease but with no notion of SPOKE's association evidence. Only together do you get "SPOKE says this gene matters for the disease, and here is the actual variant catalogued against it."

The bridge is now **required in the opposite direction from before**. biomarkerkg migrated its disease axis to MONDO, so `DOID_1612` and `DOID_7148` have 0 triples there; spoke-okn still keys DOID. The join therefore runs spoke-okn(DOID) → ubergraph `skos:exactMatch` → biomarkerkg(MONDO). The 2026-06-27 version of this transcript queried biomarkerkg directly on DOID and returned nothing.

**The pairing is now derived, not asserted.** BiomarkerKB's variant records carry the gene inside their `rdfs:label` — e.g. `Presence of dbSNP:rs1050437 sequence variation in gene HLA-C/NCBI:3107`. Extracting the symbol with a `REPLACE` and equating it to SPOKE's gene label produces a genuine gene-level join. The earlier version of this transcript hard-coded five `(DOID, gene, rsID)` triples in a `VALUES` block, so it could only confirm pairs already known to the author; this query discovers them.

**Why this answers the question.** Both gene lists are immediately recognisable, which is the check that the derived join is sound rather than accidental. Breast cancer returns the **hereditary breast-cancer panel** almost exactly — PALB2, BRIP1, BARD1, CHEK2, BRCA2, ATM, BRCA1, CDH1 — plus the Lynch-syndrome mismatch-repair genes (MSH6, MSH2, PMS2) and TP53. Rheumatoid arthritis returns the canonical RA GWAS loci: HLA-G, PTPN2, STAT4, CCR6, PADI4, NOTCH4, IL12RB2, UBASH3A.

**The striking result is the shape of the variant counts, not the gene names.** Breast cancer has *fewer* shared genes (81 vs 140) but **48× more variants** (13,551 vs 279), and the per-gene numbers differ by three orders of magnitude — 2,842 variants in PALB2 alone against 16 in the entire top RA gene.

That is two different ascertainment regimes sitting under one predicate. The breast-cancer entries are **clinical panel-sequencing output**: exhaustive enumeration of rare coding variants across a handful of high-penetrance genes, which is why the rsIDs are mostly high-numbered singletons (`rs1555460208`, `rs1603334619`). The RA entries are **GWAS tag SNPs**: a few common, well-studied variants per locus, with low-numbered long-established rsIDs (`rs7574865` in STAT4, `rs2240335` in PADI4). A count of BiomarkerKB variants is therefore not comparable across diseases — it measures how a disease is studied, not how genetically complex it is.

```sparql
PREFIX sschema: <https://purl.org/okn/frink/kg/spoke-okn/schema/>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>
PREFIX skos: <http://www.w3.org/2004/02/skos/core#>
SELECT ?diseaseLabel (COUNT(DISTINCT ?geneSym) AS ?genesInBoth) (COUNT(DISTINCT ?rsid) AS ?biomarkerVariants) WHERE {
  VALUES ?doid { <http://purl.obolibrary.org/obo/DOID_1612> <http://purl.obolibrary.org/obo/DOID_7148> }
  GRAPH <https://purl.org/okn/frink/kg/spoke-okn> {
    ?doid rdfs:label ?diseaseLabel ; sschema:ASSOCIATES_DaG ?gene .
    ?gene rdfs:label ?geneSym .
  }
  GRAPH <https://purl.org/okn/frink/kg/ubergraph> {
    ?mondo skos:exactMatch ?doid .
    FILTER(STRSTARTS(STR(?mondo),'http://purl.obolibrary.org/obo/MONDO_'))
  }
  GRAPH <https://purl.org/okn/frink/kg/biomarkerkg> {
    ?b <http://purl.obolibrary.org/obo/OBCI_1000008> ?mondo ;
       <http://purl.obolibrary.org/obo/OBCI_1000016> ?variant ;
       rdfs:label ?bLabel .
  }
  FILTER(CONTAINS(?bLabel,'in gene '))
  BIND(REPLACE(?bLabel,'^.*in gene ([^/]+)/NCBI:.*$','$1') AS ?bmGene)
  BIND(REPLACE(STR(?variant),'^.*/snp/','') AS ?rsid)
  FILTER(?bmGene = ?geneSym)
} GROUP BY ?diseaseLabel
```

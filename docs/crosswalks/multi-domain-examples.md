# Proto-OKN Multi-Domain Integration Examples — by Theme

A catalog of **validated** cross-domain integration use cases over the Proto-OKN / OKN federation, queried through the `mcp-okn` service. Each row is a research question that **genuinely requires joining two or three knowledge graphs from different domains on a shared identifier**, run as live federated SPARQL and verified that the returned rows actually answer the question. Biomedical claims are validated against the published literature (PubMed / Paperclip); environmental, geospatial and industrial integrations are validated by their authoritative shared standard (county FIPS, NAICS, NCBITaxon, etc.) and the hand-verified join recipe.

Where the crosswalk catalog files each join under a single subject domain, these use cases are organized by the *kind of question they answer across domains* — fusing, for example, toxicology with transcriptomics and clinical medicine, or environmental regulation with hydrology and public health. The research questions themselves were generated by the model (claude-opus-4-8): for each use case the model proposed a question that exercises the shared identifier, then ran and validated it.

- **Federation endpoint:** https://apps.okn.us/federation/sparql
- **Model:** claude-opus-4-8 · **Date:** 2026-06-17
- **Coverage:** 24 multi-domain use cases — **Biomedical & Molecular (11), Geospatial / County & ZIP (10), Industry & Supply Chain (3)** — spanning 14 three-KG and 10 two-KG integrations.
- **ID scheme:** `MD<use-case#>` (e.g. `MD01`, `MD14`, `MD24`).

## Methodology

**Source corpus.** Every row corresponds to a standalone chat transcript (Markdown) produced in this folder by running a single cross-domain use case live against the Proto-OKN / OKN federated SPARQL endpoint through the `mcp-okn` service.

**Question generation.** The research questions were generated by the model (claude-opus-4-8), not hand-authored. For each use case the model inspected the participating graphs' schemas and the shared identifier, then proposed a question that genuinely requires the join, and ran and validated it. The resulting questions are illustrative examples of what each integration supports rather than a curated or exhaustive set.

**Integration selection.** Candidate joins were drawn from the `mcp-okn` crosswalk registry and `get_join_strategy` recipes — each supplying the shared identifier, the predicate/role on each side, the IRI-normalization rewrite needed to make the graphs' identifiers literally equal, and a verified non-zero row count. A use case was only written up once a join returned rows that genuinely answered the research question.

**Per-question workflow.** Each transcript followed the same sequence: (1) `list_kgs` / `describe_kg` to choose the graphs; (2) `get_schema` on each graph to learn its classes, predicates and property names; (3) `probe_namespaces` where the join key is an ontology term, to confirm which identifier scheme actually populates the predicate (e.g. DOID vs MONDO, Ensembl vs Entrez vs symbol); (4) `get_join_strategy` (falling back to `find_crosswalks` only on an `unknown` result) to fix the bridge; and (5) one or more `sparql_query` calls scoping each graph with `GRAPH <https://purl.org/okn/frink/kg/{shortname}> { … }` so a single query spans multiple named graphs.

**Bridge identifiers.** The "Bridge identifier(s)" column names the shared key the join is built on. Direct joins use a single key present in every graph (Ensembl, Entrez, PubChem CID, CAS, HP, MONDO, DOID, NAICS, county FIPS, ZIP5). Where two graphs key the same entity differently, an intermediate mapping is noted in parentheses — e.g. SPOKE's Ensembl↔Entrez bridge linking PanKgraph to GXA, or GeneLab's model-organism→human ortholog mapping.

**Theme grouping.** Each use case is filed under the kind of cross-domain question it answers: Biomedical & Molecular (gene, protein, chemical and disease integrations), Geospatial / County & ZIP (place-based joins on FIPS or ZIP), and Industry & Supply Chain (NAICS-keyed manufacturing and facility joins). Within a group, rows are ordered by use-case number. The same knowledge graph can appear across several groups — SPOKE-OKN, for instance, contributes to molecular, geospatial and environmental use cases alike; placement reflects the question being asked, not the graphs alone.

**Validation.** Biomedical results were checked against the PubMed MCP server (https://pubmed.mcp.claude.com/mcp) and the Paperclip MCP server (https://paperclip.gxl.ai/mcp), a full-text biomedical corpus, for biological plausibility (known disease genes, AOP mechanisms, prognostic markers, drug indications). Environmental, geospatial and industrial results were validated by construction on their authoritative shared standard (county/state FIPS, NAICS, CAS, MONDO/DOID/HP) together with the hand-verified join recipe, and corroborated by web sources where applicable. Only use cases whose live query returned rows that demonstrably answer the question are included.

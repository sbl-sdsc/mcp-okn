# Proto-OKN Cross-KG Crosswalk Examples — by Domain

A per-domain catalog of **validated** two- and three-knowledge-graph integration crosswalks over the Proto-OKN / FRINK federation, queried through the `mcp-okn` service. Each row is a research question that **genuinely requires joining knowledge graphs on a shared identifier**, run as live federated SPARQL and verified that the returned rows actually answer the question. Biomedical claims are validated against the published literature (PubMed / Paperclip); environmental, geospatial and industrial integrations are validated by their authoritative shared standard (county FIPS, NAICS, NCBITaxon, etc.) and the hand-verified crosswalk.

The research questions themselves were generated by the model (claude-opus-4-8): for each verified crosswalk, the model proposed questions that exercise the shared identifier, then ran and validated them. The questions are illustrative of what each crosswalk can answer, not a curated or exhaustive list.

- **Federation endpoint:** https://apps.okn.us/federation/sparql

## Methodology

**Source corpus.** Every row corresponds to a standalone chat transcript (Markdown) produced in this folder by running a single crosswalk question live against the Proto-OKN / FRINK federated SPARQL endpoint through the `mcp-okn` service.

**Question generation.** The research questions were generated by the model (claude-opus-4-8), not hand-authored. For each verified crosswalk, the model inspected the two (or three) graphs' schemas and the shared identifier, then proposed questions that genuinely require the join, and ran and validated each one. The resulting questions are illustrative examples of what each crosswalk supports rather than a curated or exhaustive set.

**Crosswalk selection.** Candidate joins came from the `mcp-okn list_crosswalks` registry (75 hand-verified recipes, verified 2026-06-12). For each pair (or triple) of knowledge graphs, `get_join_strategy` supplied the precomputed join recipe — the shared identifier, the predicate/role on each side, the IRI-normalization rewrite needed to make the two graphs' identifiers literally equal, and a verified non-zero row count. A crosswalk was only written up once a join returned rows that genuinely answered the research question.

**Per-question workflow.** Each transcript followed the same sequence: (1) `list_kgs` / `describe_kg` to choose the graphs; (2) `get_schema` on each graph to learn its classes, predicates and property names; (3) `probe_namespaces` where the join key is an ontology term, to confirm which identifier scheme actually populates the predicate (e.g. DOID vs MONDO, Ensembl vs Entrez vs symbol); (4) `get_join_strategy` (falling back to `find_crosswalks` only on an `unknown` result) to fix the bridge; and (5) one or more `sparql_query` calls scoping each graph with `GRAPH <https://purl.org/okn/frink/kg/{shortname}> { … }` so a single query spans multiple named graphs.

**Bridge identifiers.** The "Bridge identifier(s)" column names the shared key the join is built on. Direct joins use a single key present in both graphs (Ensembl, Entrez, UniProt, CAS, DrugBank, PubChem CID, NCBITaxon, DOID, MONDO, HP, MeSH, county FIPS, state FIPS, ZIP5, NAICS). Where the two graphs key the same entity differently, an intermediate hub graph supplies the mapping and is shown with an arrow and the bridge graph in parentheses — e.g. `MONDO ↔ OMIM (ubergraph)`, `CHEBI ↔ CAS (ubergraph bridge)`, or `HGNC ↔ Entrez (Wikidata bridge)`. The bridge graph (`ubergraph` or `wikidata`) appears in the Knowledge-graphs column only when it carries the mapping; it contributes no domain content of its own.

**Domain grouping.** Each crosswalk is filed under its primary subject domain. The eleven domains are listed alphabetically (Anatomy & Cell Type, Chemicals, Disease & Phenotype, Environmental Toxicology, Function & Pathways, Genes, Geospatial, Industry & Supply Chain, Proteins, Social Determinants & Services, Taxonomy). Within a domain, rows are ordered by crosswalk number then question number. The same knowledge graph can appear across several domains (e.g. SPOKE-OKN supports gene, disease and geospatial crosswalks); placement reflects the question being asked, not the graphs alone. The **Anatomy & Cell Type** domain (added 2026-06-23) covers the UBERON/CL axis: BioHealthKG's UMLS-keyed anatomy concepts bridged to GXA and SPOKE-GeneLab tissues (BH9–BH10), and the direct UBERON/CL joins among SPOKE-GeneLab, GXA and ProKN (AN1–AN4).

**Validation.** Biomedical results were checked against the PubMed MCP server (https://pubmed.mcp.claude.com/mcp) and the Paperclip MCP server (https://paperclip.gxl.ai/mcp), a full-text biomedical corpus, for biological plausibility (e.g. known disease genes, AOP mechanisms, prognostic markers). Environmental, geospatial and industrial results were validated by construction on their authoritative shared standard (county/state FIPS, NAICS, NCBITaxon, MeSH/DOID/MONDO) together with the hand-verified crosswalk, and corroborated by web sources where applicable. Only crosswalks whose live query returned rows that demonstrably answer the question are included.
